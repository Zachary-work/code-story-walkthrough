The agent skill

Three prompts. The skill does the rest.

The code-stories skill teaches your agent to write the stories and to answer your comments. It works with Claude Code and with other agents that read skill folders.

Create the stories

After the agent finishes a change on a branch.

Prompt
Create code stories for this branch

Answer your comments

After you write review comments in the editor.

Prompt
Read and address my review comments

Refresh the stories

When the panel tells you that the code changed after the stories were written.

Prompt
Refresh the code stories so every changed line is covered

Create the stories

What the agent does when you ask for stories.

The agent reads the real files. It does not guess a call path from names. If the validator finds an error, the agent goes back and corrects the steps.

  1. Find the change

    The git diff from the merge base.

  2. Read the changed code and its callers

    Up to an entry point.

  3. Group the change into stories

    One behaviour, one call path.

  4. Write the steps

    One function per step, signature first.

  5. Add a sample, the tests, and the places to look closely

    Sample values come from a test when a test exists.

  6. List the files that are in no story

    Each file with a reason.

  7. Run the validator

    Correct every error, then tell you the result.

The validator

A script keeps the agent honest.

The skill includes a script that compares the stories with the git diff. The validator makes sure that:

  • Each quoted line is in the file, at that line number.
  • A changed line is not labelled as unchanged.
  • Each named test exists.
  • Each changed file is in a story, or is left out with a reason.

Answer your comments

Each comment gets one of three answers, in the same thread.

changed

The comment is correct. The agent changed the code and says where.

declined

The agent did not change the code. It gives the reason.

answered

The comment was a question. The agent answers it.

Only you resolve a thread. The agent does not close your comments.

Story sets

Each change has its own folder.

Two changes that you work on at the same time do not overwrite each other. The folder has the name of the branch. The panel shows the stories of the branch that is checked out.

The stories are review data for your working copy. Add .stories/ to .gitignore, unless you want to share the stories with the pull request.

.stories/
  feature-promo-codes/
    stories.json      the agent writes it
    comments.json     you and the agent write it
  fix-tax-rounding/
    stories.json
    comments.json
